## Open questions

- **Tag → color mapping** — _resolved_: shipped `src/lib/tag-colors.ts` with the handoff's 8-slot oklch palette. Tag → slot is hash-based (deterministic, case-insensitive, trimmed). Used by [TagPill](../src/components/post/tag-pill.astro), graph node fills, mini-graph node fills, [tag chip swatch](../src/components/ui/tag-chip.astro), and the `#tag` mention on the [featured panel](../src/components/post/featured-panel.astro).
- **Tag schema migration** — _resolved_: content-collection schema accepts both `tags` and `topics` and normalizes to `tags` via `.transform()`. `tags[0]` continues to act as the primary tag by convention. Existing Obsidian posts using `topics` keep working unchanged.
- **Graph JS approach** — _re-resolved_: React island via `client:only="react"`. The original "Astro page + vanilla JS module script" plan was overridden when phase 5 shipped — see [ADR-003](decisions/ADR-003-graph-view-react-island.md) for the load-bearing reason. Astro-first remains the default for static chrome.
- **Edge derivation** — _resolved_: build-time wikilink scanner in [`src/lib/wikilinks.ts`](../src/lib/wikilinks.ts) + [`src/lib/post-graph.ts`](../src/lib/post-graph.ts). Regex-based, runs in the page frontmatter on SSR. See [ADR-005](decisions/ADR-005-wikilink-edges-obsidian-workflow.md) for why wikilinks (and not shared tags) — the author manages posts in Obsidian.

## Update protocol

When a phase ships:

1. Flip its status to ✅.
2. Link the merged PR (or commit SHA on `main`).
3. Append any concessions or carry-overs under **Notes**.
4. If the phase produced a new architectural decision (a token-system pivot, dropping a feature, choosing one rendering strategy over another), file an ADR and link it from **Decisions log**.

When a phase changes scope mid-flight:

1. Update **Notes** with the new shape.
2. If the change is large enough that the original phase doesn't make sense anymore, split it into two rows rather than rewriting history.
